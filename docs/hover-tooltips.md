# Hover hints

`components/shared/HoverTooltip.qml` presents passive hints in the source control’s monitor. It uses a `PanelWindow` with an empty `Region` input mask, no keyboard focus, overlay layer, and ignored exclusive zone. It never owns pointer actions. The source retains clicks, keyboard commands, and Accessible labels.

Text is plain, wraps within the selected monitor, and follows current Theme body/font/surface/border tokens. No transition animation is used. The hint opens after the hover delay, opens immediately on focus, closes on leaving the target/focus or disabling/hiding it, and dismisses on Escape while its source window has keyboard focus. Placement leaves 16 logical pixels around the pointer and avoids the full source target; it tries below, above, right, left with an 8 pixel screen inset. It hides when no safe position exists. Layer surfaces resolve documented panel anchors/margins plus window-local item coordinates; Qt global mapping does not reliably expose a Wayland layer’s position. Floating-window sources use global mapping. Multiple hints share arbitration in TooltipPlacement.js. Only displayed hints sample position, every 50 ms, for scrolling and window movement.

DesktopButton preserves attached `ToolTip.text` callers but disables Qt’s default popup. MediaStrip uses the shared hint and prevents parent/transport hints competing; transport actions are keyboard operable. For rich hints, pass a `Component` to `contentComponent`; Loader gives its item the bounded width. Rich content must remain passive and wrap its text. `preferredWidth` limits its width. Very tall content is clipped to the monitor height because hints cannot own scrolling; retain full information in the actionable source panel.

Validation: `python -m unittest discover -s tests -p 'test_tooltip_*.py'`. Opt in to the private-bus Wayland check with `QUATTRO_QML_RUNTIME_TESTS=1`. Its source window remains hidden; it verifies load, focus state, native mask/focus properties and all eight theme bindings. It does not verify compositor delivery of physical pointer events or actual two-monitor visual placement. Integration additionally verified visible placement and native compositor layer bounds on both 1920×1080 monitors using a bounded, labelled private-bus fixture; no second persistent shell was started. Physical pointer delivery remains untested because native input tools are disabled; no new grants were added.
